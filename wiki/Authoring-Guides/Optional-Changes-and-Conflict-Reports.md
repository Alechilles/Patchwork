# Optional Changes and Conflict Reports

Parent: [Authoring Guides](/mod/patchwork/authoring-guides) | [Home](/mod/patchwork/home)

Patchwork is designed to let several mods touch one asset, but it also makes overlaps visible. This page explains when a failed operation can be optional and what the conflict policy does.

## Optional Operations

Operations are required by default. If one fails, the current target is rejected so Patchwork never publishes a half-applied asset. Set `Required` to `false` only when it is safe to skip that individual operation:

```json
{
  "Op": "Remove",
  "Path": "/OptionalIntegration",
  "Required": false
}
```

This is useful for a field that may not exist in an optional integration. It does not hide malformed JSON, unknown operation names, invalid pointers, or other structural errors; those must be fixed.

## Conflict Reports

Patchwork compares successful effects from different definitions that affect the same target, JSON path, and kind of change. It distinguishes:

- same-pack versus cross-pack overlaps; and
- redundant identical changes versus material overlaps.

Reports intentionally hide written values and fingerprints. Run `/patchwork conflicts` for recent rows, or `/patchwork conflicts Server/Exact/Target.json` for one exact target. The command shows up to 32 detail rows plus an overflow count.

Changes within one definition are presumed intentional and are not conflict reports.

## ConflictPolicy

New neutral definitions may set one root-level policy:

| Policy | Result |
| --- | --- |
| `Report` | The default. Apply the patch and report overlaps it introduces. |
| `Allow` | Apply the patch but suppress report rows introduced by this definition. |
| `Reject` | Stop generation for only the affected target if this definition introduces an overlap. |

`Reject` does not stop unrelated targets. During a normal reload, it retains the affected target's previously published generated bytes when available. It is a safety choice, not ownership, locking, permission, or authorization over an asset.

The policy belongs to the later definition in Patchwork's deterministic order. Use it to communicate how your integration should behave, not to claim a shared target as yours.
