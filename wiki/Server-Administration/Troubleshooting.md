# Troubleshooting

Parent: [Server Administration](/mod/patchwork/server-administration) | [Home](/mod/patchwork/home)

Start with evidence, not repeated reloads. The server log's first Patchwork message for the affected generation is usually more useful than a later cascade of errors.

## A Patch Did Not Apply

1. Run `/patchwork status`.
2. Confirm the expected runtime is active and the neutral root is eligible.
3. Confirm the definition is below `Server/Patchwork/Patches/` in a loaded asset pack.
4. Check whether the exact target was generated, skipped, or failed.
5. Read the first matching Patchwork diagnostic in the server log.
6. Verify the target path, JSON Pointer, operation type, and condition against the source asset.

Common authoring causes are a wrong asset path, a `Replace` for a field that no longer exists, an array anchor that no longer matches, a condition that is not true, or an invalid definition field.

## The Change Is Generated but Not Visible In Game

Check the reload category. `restart-required` means the generated bytes are ready but cannot safely be confirmed live; restart normally. Do not force a generic asset reload. `stale` means Patchwork could not confirm the live target; inspect the expected host adapter or Hytale observation instead of treating disk output as proof.

## A Target Was Rejected Because of a Conflict

Run `/patchwork conflicts <exact-target>`. Identify the later definition that introduced the overlapping effect, then decide whether the changes are intentionally identical, intentionally layered, or incompatible. Change the definitions or choose the correct `ConflictPolicy`; do not use conflict policy as an ownership claim.

## Recovery States

- For `rollback-failed`, stop further reload attempts, preserve diagnostics, and restart from known-good assets.
- For `RECOVERY_REQUIRED`, let the plugin holding the lifecycle handle retry its cleanup. Do not hot-swap or install another runtime until cleanup succeeds.
- If an unexpected standalone copy wins, compare version numbers in status. Election is version-first; standalone wins only when versions are equal.

Run `/patchwork selftest` when you need to check Patchwork's isolated generation engine without changing production output. Include its result, `/patchwork status`, the affected target path, and the first relevant server-log message when asking for support.
